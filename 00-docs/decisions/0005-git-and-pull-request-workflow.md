# ADR-0005: Git and pull request workflow

- **Status:** Accepted
- **Date:** 2026-10-20
- **Deciders:** Stan (owner), Claude (proposer)
- **Related:** ADR-0004, ADR-0023, ADR-0024

## Context

Git is the only way to change Olympus. The workflow must make history readable for a learner, keep `main` always deployable, and stop Athena or Renovate from merging anything Stan hasn't sanctioned.

## Decision

1. **Trunk-based.** `main` is the only long-lived branch. Flux deploys `main`.
2. **Branch names:** `<actor>/<type>/<slug>`.
   - `actor` is one of `stan` or `athena`. Renovate uses its default `renovate/…`.
   - `type` is a Conventional Commit type.
   - Example: `athena/feat/kite-tailnet-ingress`.
3. **Conventional Commits.**
   - Types: `feat`, `fix`, `chore`, `docs`, `refactor`, `ci`, `revert`.
   - Scope: the component name, or `talos`, `bootstrap`, `cluster`, `adr`, `checks`.
   - A breaking change is marked with `!`, for example `feat(cilium)!: switch to native routing`.
4. **Squash merge only.** The PR title becomes the commit message, history stays linear, and branches are deleted on merge.
5. **The PR body follows `.github/pull_request_template.md`.** Its sections:
   - **Why**, in beginner-friendly terms
   - **What changed**
   - **Impact checklist**, generated by `mise run impact`
   - `No doc change:` lines, if any
   - **How it was verified**
   - **Learn more**, with links
6. **`main` is protected by two rulesets.**
   - **Ruleset `main-integrity`.** No bypass for anyone, Stan included:
     - a PR is required, and squash is the only merge method
     - all review threads must be resolved
     - the required check `validate` (GitHub Actions) must pass on a branch that is up to date with `main`
     - linear history is required
     - force pushes and branch deletion are blocked
   - **Ruleset `main-approval`:**
     - 1 approving review from a CODEOWNER (`* @ZiineZ` in `.github/CODEOWNERS`)
     - stale approvals are dismissed on push
     - the most recent push must be approved by someone other than its pusher
   - **Bypass actors on `main-approval`, in `pull_request` mode only** (a bypass never allows a direct push):
     - **The repository admin role (Stan).** GitHub never lets a PR's author approve their own PR. Without this bypass, Stan's own PRs could never merge. They still go through `main-integrity` (PR + `validate`).
     - **The Renovate app**, added when Renovate is installed (ADR-0023). Renovate can then auto-merge only what `.github/renovate.json5` allows, and that file changes only with Stan's approval.
     - **Athena is never a bypass actor.** Its PRs always need Stan's approval.
7. **Visibility and plan: private repo under Stan's GitHub Pro.** Pro comes from the Student Developer Pack (verified 2025-06-14; benefits expire **2027-06-14**). Rulesets on private repos need Pro.
   - **Before that expiry date, Stan reverifies.**
   - **If Pro lapses, the rulesets on a private repo stop being enforced.** The fallback is to make the repo public. Everything secret is SOPS-encrypted, so that is safe.
   - `audit` checks that the rulesets are still `active` (ADR-0024).
8. **Repository settings are code.** They live in `.github/settings/*.json` (the GitHub REST API payloads). Stan applies them with `mise run github:apply`, which needs an admin token. `mise run github:diff` reports drift. The settings:
   - **Merging:** squash only. The commit title is the PR title and the commit body is blank. The PR number is appended by GitHub, so the "why" stays one click away.
   - **Branches:** auto-merge is allowed (for Renovate). Head branches are deleted on merge. The "update branch" button is on, since checks require an up-to-date branch.
   - **Features:** Issues on (audit reports). Wiki, Projects, and Discussions off.
   - **Actions:** only `actions/*` plus an explicit allow-list (`jdx/mise-action`, and `tailscale/gitops-acl-action` when ADR-0012 lands) may run. Actions **must be pinned to a full commit SHA**. The default `GITHUB_TOKEN` is read-only, and Actions can't approve PRs.
   - **Security:**
     - Dependabot *alerts* on. Renovate reads them.
     - Dependabot *security update PRs* off. Renovate is the single writer for versions (ADR-0001 principle 4).
     - Secret scanning and push protection on, where the plan allows.
   - **Labels:** exactly `breaking`, `dependencies`, `audit`, `adr`. GitHub's default labels are removed.
9. **Commit signing:** not required for now (ADR-0026).

## Consequences

- `git log` reads as a changelog.
- Athena cannot merge its own PRs: it can't approve them, and it isn't a bypass actor.
- Stan merges his own PRs without a second reviewer. CI is his reviewer. That's an accepted trade-off for a single-owner repo.
- `main` is always the deployed state. Rolling back means `git revert` plus a PR.

## Alternatives considered

- **Merge commits or rebase merges:** noisier history for a learner. Rejected.
- **GitFlow / environment branches:** there is one cluster, so this would be pointless ceremony. Rejected.

## Compliance

- **Rulesets and settings are versioned** in `.github/settings/`. `mise run github:diff` compares them with the live repo. The `audit` skill runs this diff, or reports it if it lacks permission. *Verify which GitHub App permission Athena needs to read rulesets.*
- PR title format is checked by the `validate` workflow.
