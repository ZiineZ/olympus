# ADR-0004: Single source of truth and enforced co-changes

- **Status:** Accepted
- **Date:** 2026-10-20
- **Deciders:** Stan (owner), Claude (proposer)
- **Related:** ADR-0000, ADR-0003, ADR-0005, ADR-0006

## Context

Stan's requirement: when anything changes, *all* related config and documentation must change with it, so that no part of the repo is ever ahead of another. An instruction to "remember to update the docs" is not enforcement. The rule has to hold for Stan, Athena, and Renovate alike.

## Decision

Enforcement is built in four layers. Each layer catches what the one before it cannot. **CI is the final authority**, and the `main` ruleset requires it to pass.

### Layer 1: every fact lives once

| Fact | The single home | Everything else |
|---|---|---|
| Chart and image versions | `ocirepository.yaml` / `helmrelease.yaml` / image refs in manifests | Living docs never state versions; `inventory.md` shows them |
| Talos and Kubernetes versions | `01-talos/talconfig.yaml` **and** tuppr CRs (ADR-0023) | The one sanctioned pair, kept equal by `versions-match` and grouped in Renovate |
| Shared values (domain, VIP, LB pool, tailnet) | `03-cluster/cluster-settings.yaml` | `${VAR}` via Flux `postBuild.substituteFrom` |
| Nodes, IPs, labels, disks | `01-talos/talconfig.yaml` | Docs link to it |
| Helm values | `<component>/app/values.yaml` | Both bootstrap and HelmRelease read the same file |
| Rules and conventions | `00-docs/conventions.md` | `.claude/CLAUDE.md` imports it (`@../00-docs/conventions.md`); skills link to it |
| Per-component description, docs, ADRs | `olympus/description`, `olympus/docs`, `olympus/adr` annotations in `ks.yaml` | `inventory.md` and the co-change rules are derived from them |
| CLI tool versions | `.config/mise.toml` | CI uses mise too |

### Layer 2: generate every summary of config

- `00-docs/inventory.md` is fully generated by `mise run docs:gen`. It lists components, namespaces, chart and image versions, dependencies, nodes, IPs, Pod Security level, and the ADR links.
- CI regenerates it, and the build fails on any diff (`inventory-fresh`).

### Layer 3: machine-checked consistency (`mise run check`, identical locally and in CI)

| Check | Fails when |
|---|---|
| `render` | kustomize build + helm template + kubeconform (strict, with CRD schemas) fails for any Flux Kustomization. flate posts the rendered diff on the PR. |
| `component-shape` | A component folder deviates from ADR-0003 rule 3, or namespace ≠ folder name outside the listed exceptions |
| `orphans` | A `ks.yaml` isn't referenced by its group, or a reference points nowhere |
| `root-clean` | The root contains anything not allowed by ADR-0003 |
| `substitutions` | A `${VAR}` isn't defined in `cluster-settings`, or a defined var is unused |
| `sops-encrypted` | A `*.sops.yaml` lacks SOPS metadata, or a `kind: Secret` exists outside a `*.sops.yaml` |
| `helmrelease-defaults` | A HelmRelease misses drift detection or remediation settings (ADR-0013) |
| `policies-offline` | The repo's own ValidatingAdmissionPolicies reject a rendered manifest (ADR-0021). Tool: kyverno CLI's VAP support, *verify at implementation*, fallback is a Python evaluator. |
| `versions-match` | The Talos or Kubernetes version in `talconfig.yaml` ≠ the tuppr CRs |
| `no-versions-in-docs` | A living doc (`architecture.md`, `conventions.md`, `runbooks/`) contains a version string |
| `doc-links` | A relative link or file path in docs, `CLAUDE.md`, or skills points to something that doesn't exist |
| `adr-format` | An ADR violates ADR-0000 |
| `inventory-fresh` | The regenerated `inventory.md` differs from the committed one |
| `sync-rules` | A co-change rule is violated (below) |

### Layer 4: co-change rules (`.github/sync-rules.yaml`)

Each rule says: *"if these paths change in a PR, these paths must change too."* There are two sources of rules:

- **Global rules in `sync-rules.yaml`.** The initial set:
  - added `04-platform/*/*/ks.yaml` → a new ADR + `architecture.md`
  - added or removed `05-apps/*/ks.yaml` → `architecture.md` (app list section)
  - `01-talos/**` → a runbook under `00-docs/runbooks/` mentioning Talos
  - added `00-docs/decisions/*.md` → `conventions.md` or `architecture.md`
  - `04-platform/06-agent/**` or `.claude/**` → `architecture.md` (agent section)
  - `.github/checks/**`, `.github/sync-rules.yaml` or `.claude/skills/change/**` → `conventions.md`
  - `03-cluster/cluster-settings.yaml` → `architecture.md` (network section)
- **Per-component rules:** when a component's folder changes, every path listed in its `olympus/docs` annotation must change too, or be justified.

**Escape hatch:** a line in the PR body of the form `No doc change: <path> — <reason>`, one line per path skipped. Stan reviews every such line. There is no silent bypass.

### The `main` ruleset (ADR-0005)

- `validate` (which runs everything above) is a required status check.
- Branches must be up to date, so checks always run against what will actually be merged.

### ADRs vs living docs

ADRs are immutable history. "Update all docs" means the living docs. A superseding ADR updates the living docs in the same PR.

## Consequences

- Drift becomes a CI failure instead of a review burden.
- Checks are a small set of Python stdlib scripts in `.github/checks/`, which must themselves be maintained. Changing them goes through the same workflow (sync rule above).
- One known gap: CI cannot see live nodes. Talos config applied by hand could still differ from git. That is covered by a deferred weekly comparison job (ADR-0026).

## Alternatives considered

- **Prompt-only rules in CLAUDE.md:** not enforcement, and they don't bind humans or Renovate. Rejected.
- **pre-commit/lefthook only:** easy to bypass and not authoritative. It may be added later as a convenience (ADR-0026).
- **Docs generated entirely from code:** the "why" can't be generated. Rejected. Only summaries are generated.

## Compliance

This ADR *is* the compliance mechanism. Its own integrity is protected by the sync rule on `.github/checks/**`, and by CODEOWNERS requiring Stan's review.
