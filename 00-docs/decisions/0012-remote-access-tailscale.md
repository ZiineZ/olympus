# ADR-0012: Remote access: Tailscale operator, API server proxy, tailnet policy as code

- **Status:** Accepted
- **Date:** 2026-10-20
- **Deciders:** Stan (owner), Claude (proposer)
- **Related:** ADR-0007, ADR-0011, ADR-0024

## Context

Stan already uses the tailnet `rudd-pollux.ts.net`. Remote access must work from anywhere, without port forwarding. Day to day, humans should be **read-only** (ADR-0001 principle 3).

## Decision

1. **Tailscale Kubernetes operator** in namespace `tailscale`, at decision time v1.104.1:
   - It authenticates with a Tailscale OAuth client (scopes: Devices Core write, Auth Keys write, Services write), stored in `tailscale-operator-oauth.sops.yaml`.
   - Tags: the operator gets `tag:k8s-operator`, and the proxies it creates get `tag:k8s`.
   - Proxy resources come from a `ProxyClass` named `default`, with requests set and the `platform` PriorityClass (ADR-0022).
2. **API server proxy in auth mode** (`apiServerProxyConfig.mode: "true"`):
   - hostname `olympus-k8s`
   - `kubectl` uses `https://olympus-k8s.<tailnet>.ts.net`
   - The tailnet identity is impersonated into Kubernetes groups through tailnet policy grants.
3. **Human RBAC:**
   - Stan's tailnet identity → group `olympus:viewers` → ClusterRoleBindings to the built-in `view` and to `olympus-cluster-read`. The latter is the same cluster-scoped read role Athena uses (ADR-0024), still with no Secrets.
   - **The single exception:** Role `athena-exec` (`pods/exec` create in namespace `athena` only), which lets Stan talk to Athena (ADR-0024).
   - **Write access only through break-glass:** the admin kubeconfig generated by `talosctl kubeconfig`, stored in Stan's password manager and used only per `runbooks/break-glass.md`.
4. **The tailnet policy is code:** `04-platform/01-network/tailscale/tailnet-policy.hujson`. GitHub Actions applies it with `tailscale/gitops-acl-action`: a test on every PR, an apply on merge to `main`. It defines:
   - the tags above and `tag:olympus-node`
   - the grants for `tailscale.com/cap/kubernetes` (impersonation group `olympus:viewers`)
   - access to `tag:k8s` UIs for Stan only
   - the existing personal devices' rules, migrated in as they are today
5. **Node-level break-glass:** the Talos tailscale extension, on **zeus only** (ADR-0007), joins as `zeus` with `tag:olympus-node`. `talosctl` works over the tailnet even when Kubernetes is down.
6. Tailscale MagicDNS names are the admin hostnames (ADR-0011 tier 2).

## Consequences

- Day to day, `k9s` and `kubectl` from anywhere are read-only by construction.
- The tailnet ACLs stop being dashboard state and become reviewed code.
- One limitation: the API server proxy in multi-replica (ProxyGroup) mode depends on Tailscale Services, which is beta. The single in-process proxy is used until that is GA.

## Alternatives considered

- **Subnet router to the LAN:** coarse, and it routes everything. Rejected.
- **Exposing the API on a LoadBalancer IP to the LAN:** no identity mapping. Rejected.
- **Admin by default for humans:** the biggest source of drift in practice. Rejected.

## Compliance

- The `tailscale gitops` workflow tests the policy file on every PR.
- `audit` verifies that no ClusterRoleBinding grants write access to `olympus:viewers`.
